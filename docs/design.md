## 0. 一句话与定位

**你写机器人的"小脑"：读传感器、算控制律、驱动电机。机器人在物理里动起来：冲过头、下垂、抖、摔倒。你看着示波器找出原因，然后让它在沙暴里替镇上的猫干活。**

| 项 | 定稿 |
|---|---|
| 类型 | 控制编程解谜 / 物理沙盒 / 轻叙事 |
| 主线 | 序幕 + 16 章 × 8 关 = 128 关（每章 5 谜 + 2 障 + 1 委托，共 80 谜 / 32 障 / 16 委托）；主线 40–50 h；全收集 90 h+；游戏内手册 90–140 页；一次发布，16 章全部在 1.0 |
| 关卡节奏 | 每关一个概念，常规 10–25 min（越往后越难的关可到 20–25 min）；叙事总量 ≤ 40 min |
| 课程对照 | 控制原理（PID、整定、状态反馈、LQR 直觉）、机器人学导论（运动学、雅可比、轨迹、规划）、移动机器人（反应式、巡线、栅格）、步态与接触、概率机器人（滤波、卡尔曼、定位、建图）、强化学习入门、sim2real、系统整合（状态机、能量、多机） |
| 受众 | 程序员、工科学生、创客、Zachtronics / Turing Complete 玩家 |

**三根支柱在本作里：**

| 支柱 | 本作的形态 |
|---|---|
| 关卡解谜 | 用 PATCH 写控制器；每关一个控制概念；物理自己暴露错误（超调、下垂、振荡都不是脚本） |
| 沙盒模拟 | **自由工坊**：任选机器人、场地、现实因素，实时拖旋钮看曲线变化；委托在这里完成 |
| 剧情叙事 | 沙暴要来了。镇上每只猫都需要一台机器人帮忙，而工坊里的 KIT 想知道自己还有没有用 |

## 1. 故事

### 1.1 开场

这是三部曲的**第三部**（第 5 年夏—秋）。喵星球一开始只有电，没有计算机；前两部里，栅厅的复刻机和温室里的模型"它"先后被造出来，现在还在镇上运转。科学院批准了第三期，在深井下层、紧挨着石室的地方新建了**工坊**：一圈环形灯轨绕着石室，因为骨纹只在光源移动时才显现。

白砚已经走进了沙漠。他的信指名你，一位从没见过他的远房亲戚，做骨纹研究的继任者。信里说，工坊里的八台机器人，身体已经由镇上的机械匠按骨纹图样用手艺造好：齿轮、连杆、电机，这些喵星球本来就会。控制器是空的，因为"小脑"要靠前两部学到的东西才写得出来。信的最后一句："身体靠手艺，小脑要靠你。"

八台机器人：小车、升降机、机械臂、巡线车、平衡车、步行机、定位车，还有 **KIT**。KIT 是照骨纹第一张图造出的第一条机械臂，只有一条手臂，最先造的所以最老，啰嗦，爱讲冷笑话。

驿站长橘爷带来消息：**沙暴日**还有三个月。十年一遇的秋季沙暴会让驼队断路一周。上一次，镇上有只猫没拿到药。

审查官岑理已经在镇上住了好几年。他来看工坊，说话客气："科学院想把前两期的成果收归集中，按标准型号批量造机器人、统一控制器，不用每个镇子自己写。"他的问题合理：沙暴日没几个月了，你的控制器靠得住吗？你决定先试一下：如果三个月里你能让这些机器人派上用场，工坊就不必等标准型号。

（可选镜头：灯轨上的灯第一次转起来，石面上闪过一段关节与连杆的骨纹，KIT 手臂的影子叠在上面。灯一停就不见了。不解释。）

### 1.2 结构

16 章，每章 8 关：第 1–3 关谜，第 4 关障，第 5–6 关谜，第 7 关障，第 8 关委托；章标题、身体和逐关概念见 [syllabus.md](syllabus.md)。每章有自己的译注页、一句疯话、一处 KIT 的变化、一位委托人、委托 + 展演和回响。委托人规则：同一位镇民至多连续两章。

| 章 | 地点 | 委托人 | 镇民的需要 | 概念转折 | KIT 的变化 |
|---|---|---|---|---|---|
| 1 | 驿站货仓 | 橘爷（驿站长） | 货车每天按时刻表跑三趟，不能越跑越偏 | 驱动与感知 → 开环 | 讲第一个冷笑话："我是开环的，所以我从来不知道自己说错了。" |
| 2 | 井沿 | 橘爷 | 井沿的货车要停准，不能掉进井里 | 开环 → 闭环 | 第一次承认"你比我想的有用" |
| 3 | 井道绞车 | 银婆（守井人） | 绞车吊桶载水量每次不同，要在水位标记处停稳 | 惯性与阻尼：P → PD → PID | 讲起白砚当年也在这里卡住 |
| 4 | 井道升降机 | 银婆 | 井道升降机老是停不准层 | 数字 PID、整定、前馈与串级 | 翻出白砚的整定表，最后一行被划掉，它不肯说为什么 |
| 5 | 小学教室 | 花卷（老师） | 想要一支能指向黑板上被点到的字的教鞭臂 | 关节 → 正运动学与坐标系 | 量了自己的手臂，和图纸差了两毫米，第一次对"图纸"起疑 |
| 6 | 小学黑板 | 花卷 | 想要一只会在黑板上写字的手臂 | 关节空间 → 笛卡尔空间（逆解、雅可比、轨迹） | 问你能不能给它也装一条手臂 |
| 7 | 邮局街道 | 豆芽（邮差） | 送信车沿街道线走，绕开乱跑的猫 | 差速运动学 → 反应式行为 | 羡慕会跑的车，第一次说想去井口看看 |
| 8 | 邮局送信路 | 豆芽 | 沙暴里骑不了沙地车，需要一台会自己找路的送信车 | 反应式控制 → 规划 | 开始记你的方案名 |
| 9 | 诊所病房 | 薄荷（医生） | 又高又轻的输液架，被碰一下不倒 | 稳定系统 → 不稳定系统 | 坦白自己会摔，所以只有一条手臂 |
| 10 | 诊所走廊 | 薄荷 | 在走廊里端着药盘不洒的平衡车 | 状态反馈 → 最优、摆起与抗扰 | 看你替它的底座做状态反馈站直，第一次站稳时没有讲笑话 |
| 11 | 驼道 | 阿砾（驼队向导） | 步行机沿驼道驮水，能转弯、停步 | 连续控制 → 节律 | 第一次走路（玩家写的步态） |
| 12 | 风蚀岩 | 阿砾 | 去风蚀岩坡上取回驼队水囊的步行机 | 节律 → 接触、地形与能耗 | 底座在沙地上打滑，主动问你怎么防滑，没有讲笑话 |
| 13 | 扬沙场院 | 岑理 | 他要一台读数可信的测斜仪 | 相信传感器 → 怀疑传感器（滤波、融合、卡尔曼） | 岑理指出它的角度读数一直偏了 2°，它沉默了一会儿 |
| 14 | 场院的房间 | 岑理 | "没有星标定位，你的车知道自己在哪吗？" | 里程计 → 信念 → 定位与建图 | 承认它一直不知道白砚去了哪 |
| 15 | 驿站车队场 | 橘爷（回来） | 驼队来了十台不同的车，开工前逐台体检与整定 | 理想仿真 → 现实（辨识、标定、学习） | 用你写的控制器装上第二条手臂 |
| 16 | 全镇 | 所有镇民 | 沙暴日 | 整合：状态机、能量、多机协作 | 在沙暴日值班表上写下自己的名字，第一次说"我们"而不是"你" |

### 1.3 结局

终章委托结束后，岑理提出科学院的方案：把你的控制器收归集中，按标准型号批量造机器人，统一控制器，"不用每个镇子自己写"。

| 抉择 | 结局 |
|---|---|
| 交给科学院 | **远航**：标准控制器出现在全星的机器人里；工坊关门，KIT 被留在井边当路标 |
| 留在镇上，开源给镇民 | **灯下**：工坊重新开门，花卷带学生来上课，KIT 用两只手教他们写第一行 PATCH |

两个结局都揭开白砚真相的最后一块：骨纹只在光移动时出现，身体的知识不能在井底读，得走出去学。他带着一台会自己学走路的机器人走进了沙漠，不是放弃。随后是最后的译注：「星空先回响了一次。轮到我们了。」结局不影响任何关卡。

### 1.4 在三部曲里的位置

- **承接前两部：** 沙暴日用到前两部造出的东西：栅厅的机房（第一部）、"它"的沙暴号和出行预报（第二部）。15-5 只写奖励程序，呼应第二部第 7 章的奖励劫持。KIT 在前两作里只是石影里一条机械臂的剪影，这一作它才醒着出场。
- **前作结局继承：** 第二部选了"远行"，沙暴日的预报就改成从星都发来的电报；第一部选了"星都"，机房是科学院借回来的。没有前作存档时按"留下"处理。关卡与判分都不变。
- **三部曲的终点：** 本作通关时，如果本机还有前两作的通关存档，追加一页"最后的译注"（圣经 §2.4）。

## 2. 核心玩法

### 2.1 PATCH：控制器语言

一个程序是若干行，每个控制 tick（50 Hz）从上到下执行一遍。每行写一个目标（寄存器 `r0..r7` 或执行器），读来源（寄存器、传感器、上一 tick 的执行器值、常数、旋钮）。

```
SUB  r0, target, pos            ; 误差 | error
PID  motor, r0, @kp=2, 0, @kd=0.8
```

没有循环和跳转：任何程序都不会卡死，"行数"可以直接当指标。这就是真实嵌入式控制循环的形状（读 → 算 → 写，固定周期），也和 PLC / Simulink 框图一一对应。

| 组 | 指令 | 解锁 |
|---|---|---|
| 搬运 / 算术 | MOV ADD SUB MUL DIV | 第 1 章 |
| 比较 / 选择 | MIN MAX CLAMP SEL ABS | 第 1 章 |
| 有状态 | INTEG DERIV LPF | 第 3 章（LPF 在 4-1 讲透） |
| 复合 | PID（先手搭 P+I+D，4-4 故障关后解锁） | 第 4 章 |
| 三角 | SIN COS ATAN2 ACOS SQRT | 第 5 章 |
| 概率 | EXP GAUSS | 第 14 章 |

寄存器在 tick 之间保留值（一行可以读到自己或后面的行上一 tick 写下的值），所以状态机的"当前模式"、步态的相位累加器都是普通寄存器，不需要新指令（16-1 专门讲）。

**旋钮 `@name=value`：** 任何常数都可以写成旋钮，显示为滑杆，**仿真运行时拖动立即生效**；验收时取当前值；不计入行数。这是本作"调参手感"的核心交互。

**"你写判断，引擎做苦力"：** 规划、滤波、学习这类重复计算由引擎完成并可视化，玩家只写其中有判断的那一部分。语言仍是同一套 PATCH，只是写的目标不同：

| 程序 | 玩家写 | 引擎做 | 章 |
|---|---|---|---|
| 代价程序 | 每个格子的 `cost` | Dijkstra / A*，动画展示扩展 | 8 |
| 似然程序 | 每个粒子的权重 `w` | 预测、加权、重采样，显示信念云 | 14 |
| 奖励程序 | 每 tick 的 `reward` | 表格 Q 学习，显示 Q 表与学习曲线 | 15 |
| 辨识程序 | 从阶跃响应估计 `est` | 与真实参数比较 | 15 |
| 权重程序 | LQR 的 Q、R 权重 | 求解增益，显示闭环响应 | 10 |

### 2.2 试验台与验收

| 模式 | 用途 | 特点 |
|---|---|---|
| 试验台 | 摸索、调参 | 无限时长；拖旋钮立即生效；方向键推机器人、鼠标拖目标；示波器滚动 |
| 验收 | 判定 | 固定时长、固定种子；跑公开 + 隐藏用例；可回放、单步、对比参考曲线 |

### 2.3 现实因素（贯穿全程的难度曲线）

`Real`：延迟、噪声、偏置、质量倍率、死区、增益。每章多打开一点，HUD 上用"现实度"仪表显示：

| 章 | 打开 | 玩家感受 |
|---|---|---|
| 1–2 | 无（个别关单独演示一项：1-2 饱和、1-5 读数噪声、1-7 开环累积偏差、2-6 读数延迟） | 理想世界 |
| 3 | 质量 ±10% | 同一组参数在不同车上表现不同 |
| 4–6 | + 传感器噪声 | D 项开始抖 |
| 7–10 | + 1 tick 延迟 | 增益太高会振荡 |
| 11–12 | 沿用；场地属性（摩擦、坡、台阶）进场 | 同一步态换地面就失效 |
| 13–14 | + 偏置、漂移 | 积分会跑偏 |
| 15 | + 死区 + 未知参数 + 更大延迟 | 先测量，再控制 |
| 16 | 全部 | 现实不给重来 |

隐藏用例来自同一现实分布、不同种子：把旋钮调到只对公开用例有效的方案会在提交时失败。

## 4. 沙盒：自由工坊

自由工坊就是关卡用的那个模拟器，去掉了目标：

- **任选：** 已解锁的机器人、场地（平地 / 坡 / 墙 / 井沿 / 井道 / 网格地图 / 风蚀岩 / 房间）、现实因素（每项一个滑杆）。
- **任写：** 已解锁的全部指令与程序类型；旋钮实时生效；可以推、拖目标、画路径、放障碍。
- **任看：** 全部已解锁的观察工具。
- **作品：** 多个存档位；分享码导出 / 导入；导入后本机重跑验证。

### 4.1 委托（每章第 8 关）

委托是沙盒里的一道开放题，目标来自镇民：给场景和评估函数，**不给初始方案**，可用全部已解锁零件。共 16 个，每章最后一关。参考解至少两条不同思路（例：4-8 升降机可以用 PID + 抗饱和，也可以用前馈 + P），CI 校验都可达。

委托通过后进入**展演**：镇民在场，机器人用玩家的方案运行，玩家实时干预；屏幕角落显示实时指标，记录"扛住的最难一次干预"作为截图素材。随后镇民问一个"为什么"，玩家在自己的回放上指证（§5.2）。

### 4.2 开放题（48 道，每章 3 道）

只给目标和评估函数，有直方图。例：

- 用最少行数让平衡车从下垂位置摆起并保持；
- 机械臂在 2 s 内画一个五角星；
- 不用 PID 指令完成井道升降机；
- 定位车在两次"绑架"后仍能找回位置；
- 步行机走完楼梯而不摔。

## 5. 剧情教学

### 5.1 故障关：先指证，再修

每章第 4 关和第 7 关是一台出了毛病的机器人（通常是 KIT 或镇民"自己改过"的控制器），全作 32 道。故障关排在它要检验的概念之后。玩家先在回放里点出"问题第一次出现的时刻和信号"，再修。

正确区间由核心层计算：`Evidence { why, t0, t1, signal }`，`why` ∈ { 超调、振荡、饱和、积分饱和、漂移、丢线、摔倒、发散 }，另需新增 { 冻结、越界、失步、卡死、放大 }（syllabus.md 汇总）。例：积分器在第 1.4 s 饱和；延迟导致相位落后的第一个峰。

### 5.2 讲给镇民听

委托展演后（每章第 8 关之后），镇民问一个"为什么"，玩家在自己方案的回放上指证。16 章各一个：

| 章 | 镇民的问题 | 指证 |
|---|---|---|
| 1 | 橘爷："它为什么每趟都停在同一个地方？" | 读数校正把 `pos` 拉回刻度的那一刻 |
| 2 | 橘爷："它怎么知道离井沿还有多远？" | 测距信号让电机开始减速的那一刻 |
| 3 | 银婆："桶里水多水少，它为什么都停得稳？" | 载重变化后 D 项开始压住超调的时刻 |
| 4 | 银婆："升降机为什么停之前会慢下来？" | 速度内环开始压住位置外环输出的时刻 |

## 6. 工坊 Hub

- 2.5D 手绘纵剖面：工坊在深井下层，环形灯轨绕着石室，回响石就在隔壁；窗外是井口镇，镜头可沿井道向上平移到镇上的八个区域：驿站（1、2、15）、井道（3、4）、小学（5、6）、邮局（7、8）、诊所（9、10）、驼道与风蚀岩（11、12）、扬沙场院（13、14）、沙暴日的全镇（16）。
- 16 个工位，每章一个，未开时盖着防尘布。委托（每章第 8 关）完成后，那台机器人**用玩家的控制器**在镇上的那个地点实时工作：货车在井沿来回、升降机在井道里运行、手臂在黑板上写字、送信车在街上跑。
- 回响：每完成一章，灯轨上的灯转过石室，回响石亮起一段骨纹，低鸣顺着井道传上去，风塔光束扫过镇子，点亮那个地点（圣经 §5.1 共用演出）。
- 墙上贴着玩家的最佳示波器曲线；沙暴日倒计时日历。
- 点 KIT 打开档案、手册、设置。

## 7. 美术与音频

**美术方向"工坊黄昏 / 蓝图与钢"：** 机器人侧视、平面化，钢蓝与安全橙，轮廓清晰；接触点有灰尘，碰撞有火花，力用半透明箭头。编辑器是深色蓝图网格，块按类型着色（传感器青、执行器橙、寄存器白、有状态块紫）。示波器的磷光绿只用在示波器里。窗外天色随章节推进：黄昏（1–4）→ 夜（5–8）→ 起沙（9–12）→ 扬沙（13–15）→ 沙暴（16）→ 黎明（结局）。八台机器人剪影各有辨识度，可直接做商店图阵容。

**动效原则：** 机器人的运动 100% 来自仿真，美术只加不改变状态的修饰（残影、灰尘、电机发热变色）。

**音频：** 风沙、远处的驼铃、电机待机嗡鸣。**电机声由仿真驱动**：音高 ∝ 转速，噪声 ∝ 控制量抖动，所以 D 项太大是听得出来的。每章一首分层曲；沙暴日加入风啸与沙粒敲打。

## 8. 技术

- `ooe_core`：纯 Rust、无 Bevy；`sim`（Cart、Lift、Pole、Arm、Rover、Walker、Tilt、Corridor 已实现；新增 Grid、Room、Walker 地形）、`lang`/`ctl`（PATCH，新增旋钮、GAUSS、EXP）、`plan`（Dijkstra/A*）、`pf`（粒子滤波 200 粒子）、`learn`（Q 学习 + 域随机化）、`grade`（判分 + `Evidence`）、`diagnose`（规则表）、`content`（每章一个文件，共 16 个；128 关 + 16 个展演问题 + 48 道开放题）、`save`。
- `ooe_app`：Bevy 0.20，`oo_kit` UI；画面：标题、工坊 Hub、章节、简报、工作台、结算、展演、自由工坊、档案 / 手册 / 设置。
- 性能：单用例 10 s 仿真 < 2 ms；一次验收 < 50 ms；Q 学习训练 300 episode < 400 ms；粒子滤波 < 0.3 ms / tick；验收在后台线程。
- 调试变量：`OOE_FRESH / LANG / SCREEN / TASK / REF / RUN / SCREENSHOT`。
- 引擎需求：旧 48 关所需见 [levels.md §引擎需求](levels.md#引擎需求)；80 个新关新增的部分见 [syllabus.md §新引擎能力](syllabus.md#新引擎能力)。levels.md 由大纲重建后合并为一份。
